## 1. 当前主录入链总览

### 1.1 入口与 API

| 项 | 当前事实 |
|----|----------|
| QuickInput 主提交 | `POST /api/v2/inputs`（`QuickInput.tsx` → `runIngestJob`） |
| QuickInput 是否调用 parse | **否**。主链不调用 `POST /api/v2/parse` |
| 可选辅助 | `POST /api/v2/optimize-input`（「优化输入」），与主保存 **独立** |
| Ingest V2 关闭（前端） | `resolveIngestV2ForClient()` 为 false → `onError` 并 **return**，无 parse 回退 |
| Ingest V2 关闭（服务端） | `POST /api/v2/inputs` 返回 **403**，错误码 `INPUT_INGEST_DISABLED` |

开关逻辑见 `src/lib/ingest/ingest-v2.ts`：环境变量 `INGEST_V2` / `NEXT_PUBLIC_INGEST_V2` → 开发模式默认开 → 生产查 `feature_flags.ingest_v2`。

### 1.2 主链一句话

**用户输入 → QuickInput 创建 session 卡（`parsing`）→ `POST /api/v2/inputs` → `ingestFull` / `classifyInput` → 写入 `inputs` / `input_units` → 无需澄清则 `createRecordSafely` 直写 `records`，否则返回 `pending` → 用户经 `answer` / `skip` / `cancel` / `defer` 处理 → 满足条件时 `createRecordSafely` → `records` 为正式态。**

后端编排入口：`src/app/api/v2/inputs/route.ts`；分类：`src/lib/ingest/pipeline.ts` → `classifyForIngest` → `src/lib/ai/classify-input.ts`。

## 2. 前端时间轴会话卡

### 2.1 标识规则

| 概念 | 规则 |
|------|------|
| `client_session_id` | 提交时生成：`crypto.randomUUID()`（不支持时降级随机串） |
| 列表主键 `id` | `session:${client_session_id}` |
| 与澄清面板 | `IngestClarifyState.client_session_id` 与上述一致 |

实现：`RecordsClient.tsx`（`handlePendingCreated`）、`QuickInput.tsx`（`pendingTokens`）。

### 2.2 SessionLifecycle

类型定义（`RecordsClient.tsx`）：

- `parsing`
- `awaiting_confirmation`
- `deferred`
- `saved`
- `cancelled`
- `failed`

**实现备注**

| 状态 | 是否实际赋值 |
|------|----------------|
| `parsing` | 是。`onPendingCreated` 时 |
| `awaiting_confirmation` | 是。`POST /api/v2/inputs` 返回 `pending` 时 |
| `deferred` | 是。`answer` 返回 `deferred: true` 时 |
| `cancelled` | 是。用户「取消本轮录入」时 patch |
| `failed` | 是。API 失败或空响应时 |
| **`saved`** | **否。仅类型联合中存在，代码无 `lifecycle: 'saved'` 赋值** |

**成功入库后**：调用 `onPendingResolved`，**从 `pendingInputs` 移除会话卡**，时间轴展示真实 `record`（带 DB `id`），**不会**先变成 `saved` 会话卡。

### 2.3 sessionStorage

| Key | 内容 |
|-----|------|
| `teto_records_pending_inputs_v1` | 会话卡列表（`PendingInputDraft[]`） |
| `teto_records_ingest_clarify_v1` | 澄清面板当前项 + 排队队列（`QuickInput.tsx`） |

刷新后可恢复 **deferred / 待确认** 相关快照；直入库成功项已移除，不在此列表。

### 2.4 UI 表现（已核实）

- **`failed`**：`RecordItem.tsx` 红底、「失败」徽章；`note` 为 `errorMessage`；`RecordList.tsx` 时间轴文案「失败」。
- **`defer`**：仅前端 `lifecycle: 'deferred'` + `clarifySnapshot`；**不写 DB**（见 §5）。
- **解析中**：`parsing` + `aiPending` 脉冲「解析中」（`RecordList.tsx`）。

## 3. 后端输入态模型

录入过程载体为 **`inputs` / `input_units`**；**`records` 为正式态**。`PendingQuestion` 挂在 `input_units.pending_question`。

### 3.1 Input.status

类型定义：`src/types/inputs.ts` → `INPUT_STATUSES`。

| 状态 | 类型存在 | QuickInput 主链是否写入 `inputs.status` |
|------|----------|----------------------------------------|
| `pending` | 是 | 是。创建时若 `needsConfirmation` 为 true（短暂） |
| `clarifying` | 是 | 是。需澄清时；或 `answer` 后仍有待答 unit |
| `completed` | 是 | 是。直入库完成；或澄清结束无待答 |
| `partial` | 是 | 是。**`skip` 结束且无待澄清 unit** 时 |
| `cancelled` | 是 | 是。`cancel` 路由；`answer` 的 cancel/rewrite |
| **`failed`** | 是 | **否。主链无 `updateInput(..., status: 'failed')`** |

**注意**：`inputs/route.ts` 等处 `persistTraceSummary({ status: 'failed' })` 指 **trace 摘要**，不是 `inputs` 表字段 `status`。

### 3.2 InputUnit.status

| 状态 | 类型存在 | QuickInput 主链是否写入 |
|------|----------|-------------------------|
| `pending_clarify` | 是 | 是。创建时有 `pending_question` |
| `ready` | 是 | 是。创建时无澄清题 |
| `promoted` | 是 | 是。`createRecordSafely` 成功后 |
| `partial` | 是 | 是。**`skip` 路径** |
| `cancelled` | 是 | 是。整单取消、`keep_single` 其余 unit 等 |
| **`failed`** | 是 | **否。主链未写入** |

### 3.3 相关类型（摘要）

- **`PendingQuestion`**：见 §4。
- **`Record`**：`src/types/teto.ts`；正式记录，可携带 `input_id`、`input_unit_id`、`review_status`、`record_quality_tag` 等录入来源与质量字段，具体字段以当前类型和入库 payload 为准。

## 4. PendingQuestion 与澄清 UI

### 4.1 真实结构（`src/types/inputs.ts`）

| 字段 | 说明 |
|------|------|
| `field` | 待答字段名；复合/边界/低置信确认为 `'_confirm'` |
| `prompt` | 题面 |
| `kind` | 取值为 `select` / `text` / `datetime` / `number` |
| `clarify_class` | 可选：`compound_confirm` \| `field_clarify` \| `boundary_confirm` |
| `clarify_subtype` | 可选：如 `low_confidence_confirm` |
| `options` | `{ value, label, hint? }[]` |
| `placeholder` | 可选 |
| `ai_guess` | 可选 |

**不是前端渲染字段**：`ClarificationIssue.type`（`src/types/semantic.ts`）仅在 `classify-input` → `clarification-planner.ts` 映射时使用，**不会**原样出现在 `PendingQuestion` 上。

### 4.2 澄清分类（`clarify_class` / 启发式）

| 分类 | 判定（代码） |
|------|----------------|
| `compound_confirm` | `clarify_class === 'compound_confirm'`，或 `field === '_confirm'` 且 options 含 `split`（`QuickInput.tsx`） |
| `boundary_confirm` | `clarify_class === 'boundary_confirm'` |
| `low_confidence_confirm` | `clarify_class === 'field_clarify'` 且 `clarify_subtype === 'low_confidence_confirm'` |
| 普通 `field_clarify` | 事项/子项/时长/指标等（`clarification-planner.ts`） |

选项由 `clarification-planner.ts` 的 `toQuestion()` 生成。

### 4.3 UI 分支（`QuickInput.tsx`）

| 场景 | UI |
|------|-----|
| 复合句 | 四按钮：`split` / `keep_single` / `cancel` / `defer` |
| 边界 / 低置信（二选一） | `confirm` / `rewrite` |
| 其他 `select` | 选项列表 |
| `text` / `number` / `datetime` | 输入框 + 确认 |
| `field !== '_confirm'` | 额外显示「跳过此题」「取消本轮录入」 |

## 5. 关键动作语义

| 动作 | 行为（当前代码） |
|------|------------------|
| **split** | 复合句确认中用户选择 **split** 时：服务端晋升当前 unit，并**批量 promote** 同 input 下所有 `ready` 且未晋升的 unit；多条 `records` **共享 `batch_id`**，并通过 `record_links.derived_from` 建立来源关系（`answer/route.ts`）。代码内部对部分 `_confirm` + `confirm` 分支可能复用相近晋升逻辑，但**文档层面不应把普通 confirm 直接等同于用户选择 split**。 |
| **keep_single** | 使用 **`input.metadata.primary_unit_id`**（POST inputs 时写入，默认 `unit_index === 0`）；只晋升该 unit；**其余 unit → `cancelled`** |
| **cancel**（面板 / 选项） | `POST …/cancel` 或 `answer` 内 `cancel`/`rewrite`：**整单** `input.status = cancelled`；`pending_clarify` / `ready` 的 unit → `cancelled` |
| **rewrite** | 与 **cancel 相同后端分支**（`answer/route.ts`）；**无**单独「重新描述」API |
| **defer** | **不写 DB**；返回 `{ deferred: true }`；前端 `lifecycle: 'deferred'` + `clarifySnapshot`；依赖 sessionStorage 恢复 |
| **skip** | **立即** `createRecordSafely`；`review_status: unchecked`，`confidence_level: low`，`record_quality_tag: partial`；unit → `partial`；input 可能为 `partial` 或仍 `clarifying`（有待答 unit 时） |
| **answer**（字段题） | 答案合并进 `classifier_decision.proposed_fields`（`_confirm` 除外）；随后 **promote** 当前（或 keep_single 指定）unit；返回 `next` / `promoted_record_id(s)` |

## 8. 时间解析与已知 gap

### 8.1 涉及字段

| 字段 | 角色 |
|------|------|
| `time_text` | 原文时间表达 |
| `occurred_at` / `occurred_at_end` | 解析后的起止时间 |
| `duration_minutes` | 可与 `occurred_at` 推导 `occurred_at_end` |
| `time_anchor_date` | 锚定日期（计划/模糊时间） |
| `time_precision` | 精度；`inherited` 入库前 normalize 为 `approx` |
| `metadata.date` | QuickInput 传入的 **所选日历日**（`selectedDate`） |
| `metadata.client_time` | QuickInput 传入的客户端 ISO 时间 |
| `body.date` | `inputs/route.ts` 用于 **`ingestFull` 的 `date` 参数** |

### 8.2 `resolveTemporalFields` 优先级（`record-unit-mapper.ts`）

入库前统一经此函数（`inputs` POST / `answer` / `skip`）：

1. 已有 `occurred_at`
2. `time_anchor_date`（显式）
3. `time_text` → `inferAnchorDateFromTimeText(fallbackDate, …)`
4. `duration_minutes` + `occurred_at` → 推导 `occurred_at_end`

多 unit：**同次解析**后续 unit 可继承首个锚点（`classify-input.ts`）。

### 8.3 已知 gap（必须按 gap 描述，不可写死为已符合流程图）

| 现象 | 代码事实 |
|------|----------|
| QuickInput 传日 | `metadata.date = selectedDate`，**未传 `body.date`** |
| 清分用的 `date` | `inputs/route.ts`：`const date = body.date \|\| 服务器当天`，传给 `ingestFull` / `classifyInput` |
| `metadata.date` | 写入 `input.metadata`（且 spread 覆盖同名字段），**但不作为 classify 的 `date` 参数** |
| `client_time` | 仅写入 metadata JSON，**服务端无读取参与解析** |
| **风险** | 用户所选日 ≠ 服务器「今天」时，**AI 清分锚点可能按服务器当天**，与 UI 所选日 / `input.metadata.date` **可能不一致** |

## 10. 10 阶段 Agent Pipeline 的边界

| 项 | 事实 |
|----|------|
| 定义 | `src/lib/ai/agent-pipeline.ts`：`PipelineStage` 0–9（OBSERVE … LOG） |
| QuickInput 主链 | **不调用** `runPipeline`（`src/lib/ai/pipeline-runner.ts`） |

## 11. 当前实现与理想文档差异

对照 [记录模块.md](./记录模块.md)、[记录模块流程图.md](./记录模块流程图.md)：

| 主题 | 理想文档 / 蓝图 | 当前代码 |
|------|-----------------|----------|
| 成功后时间轴 | 状态 `saved`，可见 `record_id` | 会话卡 **移除**；正式记录用 DB `id` 展示 |
| `selected_date` / `client_time` | 参与清分 | `selectedDate` → `metadata.date`；清分用 **`body.date \|\| 今天`**；`client_time` **未读** |
| 确认交互 | 完整「确认稿」多字段面板 | **渐进式单题** + 复合/边界/低置信特例 |
| Agent Pipeline | 完整流水线 | QuickInput：**classify-input 精简链** |
| 会话态 `invalid` / `rejected` / `need_clarification` | 流程图有 | `SessionLifecycle` **无**这些枚举值 |
| `rewrite` | 像重新描述 | 后端 **等同整单 cancel** |
| `failed` | 多种失败态 | 前端会话 **`failed` 有**；`Input`/`InputUnit` **表 failed 主链不写** |
| Ingest V2 关闭 | — | 前端阻断 + 服务端 403；**无 `/api/v2/parse` 回退** |
| 直入库 vs 待确认 | 审核门后统一待确认 | 仅 `pending` 返回时才有 `awaiting_confirmation`；无澄清则 **直接入库** |

## 13. 验收与注意事项

以下场景用于对照 **当前实现**；若与理想流程图不一致，以本报告为准。

### 13.1 普通直入库

| 项 | 内容 |
|----|------|
| 输入 | 一句无歧义话；Ingest V2 开启 |
| 前端 | 短暂 `parsing` 会话卡 → **移除**；列表出现正式记录 |
| 后端 | `input.status` → `completed`；unit → `promoted`；`review_status=confirmed`，`record_quality_tag=ai_high` |
| 观察字段 | `records.id`、`input_id`、`trace_summaries` |

### 13.2 普通字段澄清（answer）

| 项 | 内容 |
|----|------|
| 输入 | 缺事项/时长等，返回 `pending` |
| 前端 | `awaiting_confirmation`；澄清面板；答题后可能 `next` 或移除会话卡 |
| 后端 | `input.status` `clarifying` → `completed`；`record_quality_tag=clarified` |
| 观察字段 | `pending_question`、`answered_questions`、`promoted_record_ids` |

### 13.3 skip

| 项 | 内容 |
|----|------|
| 输入 | 字段题点「跳过此题」 |
| 前端 | 可能进入下一题或结束 |
| 后端 | 立即有 record；`review_status=unchecked`，`record_quality_tag=partial`，unit `partial` |
| 观察字段 | `promoted_record_id`、质量三字段 |

### 13.4 cancel

| 项 | 内容 |
|----|------|
| 输入 | 「取消本轮录入」或选项 cancel/rewrite |
| 前端 | 会话卡 `cancelled`（**可能仍留在列表**直至手动清理逻辑）；该 `cancelled` 是**前端会话卡状态**，不代表生成了正式 `record` |
| 后端 | `input.status=cancelled`；相关 unit `cancelled` |
| 观察字段 | 无新 `records`（未 promote 的） |

### 13.5 defer

| 项 | 内容 |
|----|------|
| 输入 | 复合句选「暂时不确认」 |
| 前端 | `deferred`；刷新后可在**同浏览器、且 sessionStorage 未清理**的前提下恢复；点击时间轴可灌回澄清 |
| 后端 | **无** defer 专用 DB 状态 |
| 观察字段 | API `deferred: true`；`clarifySnapshot` |

### 13.6 复合句 split
